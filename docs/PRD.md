- **제품명**: 마이링크 (MyLink)
- **문서 버전**: v1.2.0 (상세 사용자 시나리오 대폭 확장)
- **작성일자**: 2026-11-09
- **문서 상태**: 확정 (Approved for Live Demo)
- **핵심 목표**: **브라우저 로컬스토리지(LocalStorage)를 활용한 프로필 페이지 단일 뷰 완성**

---

## 1. 프로젝트 배경 및 시연 전략 (Context & Demo Strategy)

### 1.1 시연 목적 (Live Demonstration Goal)
본 프로젝트는 **"Next.js와 브라우저 로컬스토리지를 활용해 나만의 링크트리 서비스를 점진적으로 만들어가는 라이브 시연"**을 위해 기획되었습니다.

한 번에 모든 복잡한 기능(대시보드, 통계, 백엔드)을 구축하지 않고, **가장 핵심이 되는 프로필 페이지가 로컬스토리지와 어떻게 연동되는지**를 먼저 시연하고 검증하는 **단계별(Step-by-Step) 접근**을 취합니다.

### 1.2 시연 범위 정의 (Scope Boundaries)

| 구분 | 포함 여부 | 주요 내용 |
|---|:---:|---|
| **현재 시연 범위 (In-Scope)** | **✅ 필수** | • 브라우저 `localStorage` 기반 프로필 & 링크 데이터 읽기/쓰기<br>• 최초 방문 시 기본 샘플 데이터 자동 초기화 (Auto-seeding)<br>• Next.js App Router 기반의 SSR Hydration-safe 렌더링<br>• 모바일 반응형 프로필 카드 UI (TDS 스타일 적용)<br>• 이메일 클립보드 복사 피커 & 외부 링크 새 탭 이동 인터랙션 |
| **추후 단계 범위 (Deferred / Out-of-Scope)** | **⏳ 차기 단계** | • 관리자 대시보드 편집기 (링크 추가/수정 폼, 드래그 앤 드롭 등)<br>• 방문자 및 링크 클릭 통계(Analytics) 분석 지표<br>• 테마 실시간 변경 커스텀 피커<br>• JSON 데이터 내보내기/가져오기 백업 모듈 |

## 2. [Phase 1: 현재 시연] 로컬스토리지 프로필 페이지 요구사항

### 2.1 [FR-01] 로컬스토리지 연동 엔진 (Storage Engine)
1. **스토리지 키 정의**:
   - `mylink_profile_data` 단일 키에 JSON 객체 형태로 프로필과 링크 목록 저장.
2. **최초 접속 시 자동 시딩(Auto-Seeding)**:
   - 브라우저 로컬스토리지를 조회하여 데이터가 없을 경우, 기본 샘플 데이터(기본 이름, 소개글, 아바타, 3개 기본 링크)를 즉시 저장.
3. **SSR Hydration Mismatch 방지**:
   - Next.js 서버 렌더링 시점과 브라우저 마운트 시점의 불일치를 방지하기 위해 마운트 완료(`isMounted`) 후 안전하게 로컬스토리지 값 동기화.

### 2.2 [FR-02] 프로필 페이지 뷰 (Profile View Components)
1. **프로필 헤더 영역**:
   - 아바타 이미지 (원형 마스크 및 fallback 처리)
   - 온라인 상태 표시 인디케이터
   - 사용자 이름 (`displayName`) 및 핸들 (`@username`)
   - 소개 문구 (`bio`)
   - 관심사/역할 뱃지 칩 목록
2. **액션 버튼 영역**:
   - 이메일 복사하기 (클릭 시 클립보드 복사 + 피드백 토스트/문구 전환)
   - 소셜 프로필(GitHub 등) 바로가기 버튼
3. **링크 목록 영역 (`list-row`)**:
   - 로컬스토리지에 저장된 활성화(`isActive: true`) 링크들을 순서대로 출력
   - 각 링크 카드: 좌측 전용 아이콘 + 제목 + 서브 설명 + 우측 화살표(Chevron)
   - 링크 클릭 시 새 탭(`target="_blank"`)으로 안전하게 오픈
4. **푸터 영역**:
   - 저작권 문구 및 로컬스토리지 연동 안내 표기

## 3. 데이터 스키마 명세 (Data Schema)

로컬스토리지 키 `mylink_profile_data`에 저장되는 단일 JSON 구조입니다.

```typescript
export interface LinkItem {
  id: string;
  title: string;
  url: string;
  description?: string;
  icon?: 'github' | 'mail' | 'web';
  isActive: boolean;
}

export interface MyLinkProfileData {
  username: string;       // 예: "seoyeonkim-glitch"
  displayName: string;    // 예: "김서연"
  bio: string;            // 소개 문구
  avatarUrl: string;      // 아바타 이미지 주소
  tags: string[];         // 뱃지 태그 배열
  socialLinks: {
    github?: string;
    email?: string;
  };
  links: LinkItem[];      // 링크 목록
  updatedAt: string;      // ISO 8601 타임스탬프
}
```

## 4. 상세 사용자 시나리오 (User Scenarios)

### 시나리오 1: [신규 사용자] 링크트리 첫 방문 및 자동 초기화
- **사용자**: 처음 마이링크 사이트에 접속한 방문자/평가자
- **목표**: 회원가입이나 세팅 없이 접속하자마자 동작하는 완성도 높은 링크트리 화면을 바로 확인한다.
- **진행 흐름**:
  1. 사용자가 웹 브라우저로 `http://localhost:3000`에 접속한다.
  2. 시스템은 브라우저 `localStorage`에서 `mylink_profile_data` 키의 존재 여부를 검사한다.
  3. 데이터가 존재하지 않음을 확인하고, 사전 정의된 기본 샘플 데이터(김서연 프로필, GitHub/포트폴리오/이메일 링크 3종)를 `localStorage`에 자동 저장(Auto-seeding)한다.
  4. 로컬스토리지에서 데이터를 읽어와 TDS 스타일의 프로필 카드와 링크 리스트를 화면에 즉시 렌더링한다.
- **예상 결과**: 빈 화면이나 로딩 오류 없이, 완성형 프로필 페이지가 즉시 렌더링된다.

---

### 시나리오 2: [방문자/청중] 링크 탐색 및 원클릭 인터랙션
- **사용자**: 링크트리 프로필을 구경하고 연락처를 확인하려는 청중 또는 채용 담당자
- **목표**: 원하는 외부 링크로 바로 이동하거나, 이메일 주소를 쉽게 복사한다.
- **진행 흐름 (A - 이메일 복사)**:
  1. 사용자가 화면 상단의 `[이메일로 연락하기]` 버튼을 탭/클릭한다.
  2. 시스템은 클립보드에 이메일 주소(`seoyeonkim@hanyang.ac.kr`)를 저장한다.
  3. 버튼 라벨이 즉시 `이메일 복사됐어요 ✓`로 변경되며, 2초 후 원래 문구로 자연스럽게 복귀한다.
- **진행 흐름 (B - 링크 카드 탐색)**:
  1. 사용자가 목록의 `GitHub 저장소` 카드를 탭/클릭한다.
  2. 시스템은 `rel="noopener noreferrer"` 속성과 함께 새 브라우저 탭으로 해당 GitHub 저장소를 안전하게 연다.
- **예상 결과**: 복사 여부를 명확히 인지할 수 있고, 원래 프로필 페이지를 벗어나지 않고 새 탭으로 링크를 탐색할 수 있다.

---

### 시나리오 3: [시연 발표자] 개발자 도구를 통한 로컬스토리지 영속성 검증 (핵심 시연)
- **사용자**: 라이브 코딩 및 아키텍처를 시연하는 발표자
- **목표**: 백엔드 서버 없이 브라우저 로컬스토리지에 데이터가 실제로 영구 저장되고 동작함을 청중에게 직접 증명한다.
- **진행 흐름**:
  1. 발표자가 브라우저에서 개발자 도구(`F12` 또는 `Cmd+Opt+I`)를 연다.
  2. `Application` 탭 > 좌측 `Storage` > `Local Storage` > `http://localhost:3000` 항목을 선택한다.
  3. `mylink_profile_data` 키에 JSON 형식으로 프로필 및 링크 배열이 저장되어 있는 것을 화면에 보여준다.
  4. 발표자가 JSON 값의 `displayName`을 `"김서연"`에서 `"홍길동"`으로 임의 수정하거나, 첫 번째 링크의 제목을 변경한다.
  5. 브라우저 새로고침(`F5` 또는 `Cmd+R`)을 실행한다.
- **예상 결과**: 새로고침 후에도 변경된 `"홍길동"` 이름과 수정된 링크가 그대로 화면에 렌더링되며, 데이터가 브라우저에 안전하게 영속되어 있음을 성공적으로 입증한다.

---

### 시나리오 4: [모바일 접속자] 소형 스마트폰 화면(320px~375px) 최적화 열람
- **사용자**: 인스타그램 바이오 링크나 모바일 메신저를 통해 접속한 스마트폰 사용자
- **목표**: 작은 모바일 기기에서도 레이아웃 깨짐 없이 쾌적하게 프로필과 링크를 터치한다.
- **진행 흐름**:
  1. 사용자가 iPhone SE, 갤럭시 등 폭 360px 이하의 좁은 모바일 화면으로 접속한다.
  2. 반응형 미디어 쿼리가 작동하여 카드 좌우 여백과 버튼 패딩이 자동으로 최적화된다.
  3. 긴 링크 제목이나 이메일 주소가 화면 밖으로 넘치지 않고 말줄임(`text-overflow: ellipsis`)으로 깔끔하게 처리된다.
  4. 모든 버튼과 링크 카드가 최소 44×44px 이상의 터치 타깃 영역을 유지하여 오터치 없이 한 손으로 편하게 클릭한다.
- **예상 결과**: 모바일 스몰 화면에서도 가로 스크롤이나 레이아웃 깨짐 현상이 전혀 발생하지 않는다.

---

### 시나리오 5: [예외 복구] 로컬스토리지 손상 및 데이터 리셋
- **사용자**: 브라우저 캐시를 임의로 조작했거나 데이터 초기화를 원하는 사용자
- **목표**: 로컬스토리지의 데이터가 비정상적인 JSON 형태이거나 손상되었을 때도 서비스가 중단되지 않고 안전하게 복구된다.
- **진행 흐름**:
  1. 로컬스토리지의 `mylink_profile_data` 값이 깨지거나 비어있는 상태에서 페이지가 로드된다.
  2. 시스템의 `JSON.parse` 예외 처리(Try-Catch)가 동작하여 오류를 감지한다.
  3. 애플리케이션 크래시를 방지하고, 즉시 기본 `DEFAULT_PROFILE` 객체를 복원하여 로컬스토리지에 재할당한다.
- **예상 결과**: 화면이 하얗게 멈추는 에러(White-screen error) 없이 안정적으로 기본 프로필 화면이 복구된다.
